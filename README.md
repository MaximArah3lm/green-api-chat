# GREEN-API Chat

**Демо:** [https://maximarah3lm.github.io/green-api-chat/](https://maximarah3lm.github.io/green-api-chat/)

Тестовое задание на позицию «Фронтенд-разработчик React».

Простой веб-интерфейс для отправки и получения текстовых сообщений в WhatsApp через [GREEN-API](https://green-api.com). Внешний вид сделан по мотивам веб-версии мессенджера.

## Что умеет

- Вход по `idInstance` и `apiTokenInstance` (проверяется через `getStateInstance`)
- Создание чата по номеру телефона (номер проверяется через `checkWhatsapp`)
- Отправка текстовых сообщений (`sendMessage`)
- Получение входящих сообщений через HTTP API (`receiveNotification` + `deleteNotification`)
- Если пишет новый контакт, чат с ним появляется в списке автоматически
- Счётчик непрочитанных, статус отправки сообщения, повторная отправка при ошибке
- Адаптив: на мобильных показывается либо список чатов, либо открытый чат

## Стек

- React 19, TypeScript, Vite
- Redux Toolkit (слайсы и `createAsyncThunk` для отправки сообщений)
- axios
- CSS Modules на SCSS, именование классов по БЭМ
- Tailwind CSS 4 — стили пишутся через `@apply` внутри `*.module.scss`, утилитарных классов в разметке нет
- oxlint, Prettier

## Подготовка инстанса GREEN-API

**Без этого шага сообщения будут отправляться, но ответы в чат не придут.** По умолчанию у нового инстанса получение входящих выключено.

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com) и создайте инстанс. Бесплатного тарифа Developer достаточно.
2. Авторизуйте инстанс: в личном кабинете откройте QR-код и отсканируйте его в WhatsApp на телефоне («Связанные устройства» → «Привязка устройства»). Статус инстанса должен смениться на `authorized`.
3. Откройте настройки инстанса и в разделе уведомлений:
   - **включите получение уведомлений о входящих сообщениях** (`incomingWebhook`);
   - **оставьте пустым поле URL вебхука** (`webhookUrl`). Если адрес указан, уведомления уходят на него, а не в очередь, из которой их забирает приложение.
4. Остальные виды уведомлений лучше выключить, приложению они не нужны: статусы отправленных сообщений (`outgoingWebhook`), сообщения, отправленные с телефона (`outgoingMessageWebhook`) и через API (`outgoingAPIMessageWebhook`), состояние инстанса (`stateWebhook`), звонки (`incomingCallWebhook`). Это необязательно, но каждое лишнее уведомление в очереди — это два лишних запроса.
5. Сохраните изменения. Инстанс перезагрузится, настройки применяются в течение нескольких минут (до 5).

`idInstance`, `apiTokenInstance` и `apiUrl` указаны на странице инстанса в личном кабинете.

## Локальный запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
git clone https://github.com/MaximArah3lm/<repo>.git
cd green-api-chat
npm install
cp .env.example .env
npm run dev
```

Приложение откроется на http://localhost:5173

### Переменные окружения

Файл `.env` необязательный, без него всё тоже работает.

| Переменная | Описание |
|---|---|
| `VITE_API_URL` | Адрес API, по умолчанию `https://api.green-api.com` |
| `VITE_ID_INSTANCE` | Необязательно. Подставляется в форму входа |
| `VITE_API_TOKEN_INSTANCE` | Необязательно. Подставляется в форму входа |

Переменные `VITE_*` попадают в собранный бандл, поэтому токен в `.env` стоит указывать только для локальной разработки.

### Команды

- `npm run dev` — дев-сервер
- `npm run build` — сборка в `dist/`
- `npm run preview` — посмотреть собранную версию
- `npm run lint` — линтер
- `npm run format` — Prettier

Для VS Code в `.vscode/` лежат настройки и рекомендуемые расширения. Нужно расширение Tailwind CSS IntelliSense, иначе редактор подсвечивает `@theme`, `@utility` и `@reference` как ошибки.

## Как проверить

1. Подготовить инстанс, как описано [выше](#подготовка-инстанса-green-api).
2. Открыть приложение, ввести `idInstance` и `apiTokenInstance`. Поле `apiUrl` можно оставить по умолчанию или вставить адрес из личного кабинета.
3. Нажать «Новый чат», ввести номер собеседника (например, `+7 900 123-45-67`) и отправить сообщение.
4. Ответить с телефона собеседника — ответ появится в чате.

## Деплой

Сайт публикуется на GitHub Pages через GitHub Actions (`.github/workflows/deploy.yml`): при пуше в `main` проект собирается и выкладывается автоматически. В настройках репозитория нужно один раз выбрать источник: Settings → Pages → Source → **GitHub Actions**.

В `vite.config.ts` указан `base: './'`, поэтому сборка работает по любому адресу, в том числе `https://<username>.github.io/<repo>/`. Роутера в приложении нет, так что отдельная настройка для SPA не нужна.

## Стили

Каждый компонент — один БЭМ-блок в своём `*.module.scss`. Имена в camelCase-варианте БЭМ: `block__element_modifier` (например, `chatItem__date_unread`). Так к классам можно обращаться через точку: `s.message__bubble`, `s.layout_chatOpen`. Sass нужен для вложенности (`&__element`, `&_modifier`), сами стили задаются через `@apply`:

```scss
@reference '../../../../styles/theme.css';

.message {
  @apply mb-1 flex flex-col items-start;

  &__bubble {
    @apply rounded-lg bg-bubble-in shadow-bubble;
  }

  &_out &__bubble {
    @apply bg-bubble-out;
  }
}
```

Размеры в стилях кратны 4 (4, 8, 12, 16, ...). Исключения — тонкие линии в 1px (границы, тень пузыря сообщения, точки фона чата).

Цвета, тени и кастомные утилиты описаны в `src/styles/theme.css`. Tailwind подключён через PostCSS (`postcss.config.js`), а не через `@tailwindcss/vite`: Vite-плагин не обрабатывает `.scss`-файлы, а PostCSS запускается уже после компиляции Sass.

## Как работает получение сообщений

Используется HTTP API, без вебхуков. Пока открыт экран чатов, хук `useNotificationsPolling` по кругу делает:

1. `receiveNotification` — сервер держит запрос до 60 секунд, пока не появится уведомление;
2. если пришло входящее текстовое сообщение — оно добавляется в store;
3. `deleteNotification` — уведомление удаляется из очереди (иначе оно будет приходить снова).

Следующий запрос планируется через `setTimeout`. При ошибке повтор идёт через 5 секунд. Если очередь пустая — не чаще раза в 2 секунды: по документации сервер сам держит запрос, но на практике пустой ответ иногда приходит сразу. При выходе из аккаунта текущий запрос отменяется.

### Если входящее сообщение не появилось

- Проверьте [настройки инстанса](#подготовка-инстанса-green-api): уведомления о входящих включены, `webhookUrl` пустой. После сохранения подождите несколько минут.
- Приложение должно быть открыто в одной вкладке: очередь у инстанса одна, и другая вкладка может забрать сообщение себе.
- В режиме разработки (`npm run dev`) в консоли браузера видно, какие уведомления пришли и почему они пропущены (группа, медиа, служебное уведомление). Если в консоли ничего нет, значит сообщение не дошло до очереди инстанса.
- Сообщения из групп и медиафайлы не показываются, по условию задания.

## Ограничения

- Только текстовые сообщения и только личные чаты (группы и медиа игнорируются) — по условию задания.
- История переписки хранится только в памяти и пропадает после перезагрузки страницы. В `localStorage` сохраняются данные входа и список чатов.
- Очередь уведомлений у инстанса одна, поэтому если открыть приложение в нескольких вкладках, они будут «забирать» сообщения друг у друга.
- Данные инстанса хранятся в `localStorage` в открытом виде. Для тестового задания это нормально, в реальном проекте запросы лучше проксировать через свой бэкенд.
- На бесплатном тарифе есть ограничение на количество чатов.
